# КП МедИИума для клиники

Задача: за один заход превратить сырые заметки со встречи в КП, которое можно
отправить клинике. Второй режим: быстро и безопасно вносить правки в уже
отправленный документ.

Контекст продукта, кейсы и позиции по данным: `~/Documents/ivanilin/ai-seo/mediium/project.md`,
`mediium/sitemap.md`, память `mediium-project`. Пример готового КП:
`assets/example-asko-med-v1.html` (первая версия, до правок; итоговые решения ниже).

## Шаг 1. Разбор встречи

Сначала файл `mediium/deals/<клиника>-discovery.md`: как устроено сейчас (запись, каналы,
люди, объём, нагрузка, метрики), что болит по порядку, возражения с ответами, что
запросить у клиники. Где запись встречи читается двояко, ставь `[уточнить]` и не
выбирай трактовку сам. Посмотри сайт клиники: виджеты чата, аналитика, мессенджеры.

## Шаг 2. Структура КП

1. **Задача клиники.** Только то, что сказали на встрече. Спорные цифры с пометкой
   «(доуточним точные показатели)». То, что у клиники работает хорошо, прямо пишем
   «не трогаем».
2. **Что даём.** Первым списком «Сразу, с первого месяца пилота»: интеграция с МИС
   и расписанием, связка с CRM, сбор базы знаний и обучение ИИ вместе с клиникой,
   согласованные каналы, ответы на типовые вопросы, запись, передача сложных случаев
   операторам, аналитика от обращения до записи и приёма. Дальше подразделы и
   «Что не входит в пилот».
3. **Как оцениваем результат.** Таблица «Показатель / Как считаем / Цель». Под ней
   «По итогам пилота клиника видит»: дополнительные записи, обращения, которые перестали
   теряться, высвобожденные часы операторов, дошедшие до приёма, деньги. Для часов и денег
   сразу пишем формулу расчёта. Для ориентира один близкий по профилю кейс.
4. **Внедрение.** Таблица этапов: подключение, база знаний и обучение ИИ; проверка и
   запуск; работа пилота. Что нужно от клиники.
5. **Юридические вопросы.** См. ниже.
6. **Стоимость.** Абзац-обоснование и таблица «Пилот, первые 3 месяца» / «Сопровождение
   после пилота». Порядок оплаты.
7. **Гарантия.**
8. **Следующие шаги.**

## Решения, которые уже приняты (не переспрашивать)

- **Цена пилота** по умолчанию 50 000 ₽ в месяц, 3 месяца. Порядок оплаты: предоплата за
  первый месяц, дальше ежемесячно. Цену не выдумывать под другую клинику без подтверждения
  владельца: если масштаб сильно другой, спросить.
- **Обоснование цены:** первые три месяца МедИИум берёт на себя значительную часть стоимости
  запуска (интеграция, база знаний, сценарии, аналитика); дальше эти работы не повторяются,
  но МедИИум ведёт весь контур, поэтому после пилота действует стоимость сопровождения.
- **Сопровождение после пилота:** «Рассчитаем после первого месяца работы, по результатам».
- **Гарантия:** клиника может остановить пилот в конце любого месяца, дальше платить не нужно.
  Возврат денег обсуждается отдельно для каждой клиники: в КП АСКО-МЕД его добавляли по
  просьбе владельца, но партнёр был против. Без явного решения владельца возврат не писать.
- **Не предлагать:** карту потерь (сложно на старте), приглашение пациентов из базы и
  исходящие звонки (в разработке, можно только в «Что не входит»), подтверждение звонками,
  если клиника довольна SMS.
- **Цели пилота.** Главная: рост собранных контактов +5–10% (контакты с сайта и из
  мессенджеров на 1000 посещений сайта, период пилота против тех же месяцев прошлого года,
  из-за сезонности). Остальное только с данными клиники. Осторожно с обещаниями, которые
  партнёр вычёркивал: «конверсия не ниже, чем у контакт-центра» и «ответ до 20 секунд»
  как цель в договоре. Бенчмарк записей через МедИИум по кейсам 12–27% обращений.
- **Кейсы:** Атмосфера (стоматология, DentalPro, amoCRM), Crocodent (стоматология, Ident),
  3D Gastro (многопрофильная, Клиентикс: 886 обращений, 237 записей, 178 приёмов, 75%).
  Брать ближайший по профилю. Другие цифры не придумывать.
- **Юридический блок:** клиника оператор ПД, МедИИум обрабатывает по поручению, поручение в
  договоре; МедИИум не хранит ПД и не передаёт третьим лицам, имя, телефон и запись уходят
  только в МИС и CRM клиники, в модель текст без имени и телефона; согласие пациента перед
  первым сообщением; факт обращения и записи это врачебная тайна, помощник не обсуждает
  диагнозы; помощник не выдаёт себя за человека. Про серверы не писать. «Юрист клиники
  утверждает» не вставлять в каждый пункт.
- WhatsApp со звёздочкой и сноской про Meta внизу.

## Шаг 3. Сборка Google Doc

HTML (стили как в примере: зелёный #0F6B5C для заголовков, таблицы с рамкой #C9D2CD,
жёлтая подсветка `.fill` только для полей, которые реально не заполнены) → Google Doc:

```bash
python3 ~/.claude/skills/mediium-kp/scripts/gdoc.py create kp.html "КП МедИИум для <клиники>: пилот на 3 месяца"
```

Скрипт печатает id и ссылку, доступ «все по ссылке могут редактировать» уже выдан.
Открыть ссылку через `open`. Ссылку записать в файл разбора и в память клиента.

Выделенный блок (например, гарантия возврата) делается уже в документе через Docs API:
`updateParagraphStyle` с `shading`, `borderLeft` и одинаковыми `indentStart`/`indentFirstLine`.
Проверять вид экспортом в PDF (`drive/v3/files/<id>/export?mimeType=application/pdf`) и чтением страниц.

## Шаг 4. Правки

Документ после отправки правят люди. **Никогда не перезаливать HTML целиком.** Порядок:

1. `gdoc.py dump <docId>`: текущий текст, таблицы с индексами и комментарии. Найти правки,
   которых нет в своей версии, и сохранить их.
2. Собрать `edits.json` (replace, del_para, set_para, del_row) и `gdoc.py edit <docId> edits.json`.
3. Снова `dump` и сверить результат.

Если владелец пересылает скриншоты с выделенным текстом без комментария, это места, которые
кто-то хочет убрать или изменить: предложить варианты и спросить, а не удалять молча.

## Шаг 5. Сообщение клинике

Коротко и по-дружески, от лица команды МедИИума: спасибо за встречу, ссылка на КП, одна-две
фразы о сути пилота, ссылка на пример отчёта https://mediium.ru/primer-otcheta/ (проверить,
что открывается), следующий шаг: созвон и уточнение цифр. Без канцелярита, без тире-цепочек,
3–6 предложений.
