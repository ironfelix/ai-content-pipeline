# SEO Optimizer — финальная SEO-упаковка статьи

## Шаг 0 — Загрузить конфиг проекта

**Определить проект** — по аргументу `project=` или дефолт `factor`:

```python
import os

# project= аргумент, если передан (напр. project=crmgroup)
# Иначе — "factor"
project_dir = "<значение аргумента project= если передан, иначе 'factor'>"

config_path = os.path.join(project_dir, "project.md")
if os.path.exists(config_path):
    with open(config_path) as f:
        project_config = f.read()
    print(f"Проект: {project_dir} → {config_path}")
else:
    project_config = None
    print(f"project.md не найден в {project_dir}/ → используем дефолты Фактора")
```

Если `project.md` найден — использовать его значения:
- `brand_name` — название бренда для SEO Title и Description
- `internal_links_map` — карта внутренних ссылок (вместо `factor/data/company-context.md` раздел 9)
- `company_context` — контекст компании для внутренних ссылок
- `search_engine` — целевой поисковик (дефолт: Яндекс)

Если `project.md` НЕ найден → фолбэк на дефолты Фактора:
- `brand_name` = «Фактор Продаж»
- `internal_links_map` = `factor/data/company-context.md` раздел 9
- `search_engine` = Яндекс

Если статья не передана — спроси: «Передай текст статьи и целевой ключевой запрос.»

## Шаг 1 — H1

Правила H1:
- Целевой запрос буквально + год
- Длина: 50–70 символов
- Без украшений и «умных» слов
- Год обязателен (повышает CTR в выдаче)
- **Год** — текущая дата известна из контекста сессии; при сомнении проверить `date +%Y`. Не писать наугад
- **Обложка:** первые ≤3 слова H1 станут первой строкой обложки (line1) в проектах с автогенерацией обложек (для factor — mu-plugin). Проверь, что они осмысленны сами по себе

Предложи **3 варианта H1** — пусть пользователь выберет:
```
Вариант 1: [буквальный ключ + год]
Вариант 2: [ключ + уточнение + год]
Вариант 3: [ключ с другим порядком слов + год]
```

## Шаг 2 — SEO Title

Правила:
- 50–60 символов (считай символы!)
- Целевой ключ в начале
- Год — желательно
- Без «|» если влезает и без разделителей

Пример:
```
❌ «Как провести аудит отдела продаж | Фактор Продаж»  (56 — ок, но слабо)
✅ «Аудит отдела продаж 2026: что проверять и как»     (48 — отлично; год всегда текущий)
```

Предложи **2 варианта** с подсчётом символов.

## Шаг 3 — SEO Description

Правила:
- 120–155 символов (считай!)
- Структура: ключ + ценность + CTA
- CTA: «Читайте в статье», «Узнайте как», «Пошаговый разбор»
- Без кавычек и спецсимволов

Пример:
```
«Аудит отдела продаж — как найти где теряются лиды, что проверить в CRM и скриптах. Чек-лист от практиков из 200+ проектов.»
(127 символов ✓)
```

Предложи **2 варианта**.

## Шаг 4 — Проверка H2

Каждый H2 должен быть самостоятельным поисковым запросом. Проверь список H2 в статье:

| H2 | Статус | Правка |
|----|--------|--------|
| [текущий H2] | ✅ / ❌ | [предложение если ❌] |

Запрещённые паттерны H2:
- «Что такое X» (информационный мусор)
- «Почему X важен» (очевидно)
- «Итог» / «Заключение» (не поисковый запрос)
- Абстрактные: «Как это работает», «Ключевые моменты»

## Шаг 5 — FAQ

Минимум 4 вопроса. Источники:
1. WebSearch «[ключ]» → блок «люди также спрашивают» в выдаче
2. Поисковые саджесты (автодополнение Яндекса/Google по ключу)
3. Wordstat — только вручную или через API при наличии токена (сайт wordstat.yandex.ru не индексируется, запрос `site:wordstat.yandex.ru` не работает)
4. Вопросы, на которые статья уже отвечает, но без явного H2

Формат вывода:
```
Q: [вопрос буквально из поиска]
A: [2-4 предложения, конкретный ответ]
```

## Шаг 6 — Обложка (cover_subtitle + cover_tag)

**cover_subtitle** — подзаголовок обложки, 3–5 слов строчными:
- Описывает угол статьи: «как выявить слабые места», «чек-лист и методология»
- НЕ повторяет H1 дословно

**cover_tag** — тег на обложке, 2–4 слова ЗАГЛАВНЫМИ через «·»:
- Жанр + год: «ПОШАГОВЫЙ ГАЙД · {текущий год}», «ЧЕК-ЛИСТ · ПРИМЕРЫ»
- Не более 4 слов

Предложи 2 варианта каждого.

## Шаг 7 — Внутренние ссылки

### 🔴 Сначала — есть ли у статьи путь в услугу

Считать ссылки недостаточно: статья может иметь 4 внутренние ссылки и при этом никуда не вести. **Обязательная проверка: есть ли в ТЕЛЕ статьи хотя бы одна контекстная ссылка на коммерческую страницу — и уводит ли она в нужную услугу.**

Ссылка в шапке, подвале или сквозном баннере **не считается**: она есть на каждой странице сайта и не является путём из этой статьи.

Замер crmgroup за 22.07–18.08 (Метрика 84993793), из-за которого этот чек появился:

| | |
|---|---|
| Инфо-визитов (глоссарий + блог) | 1 604 |
| Из них дошли до коммерческой страницы | **0** (в предыдущем периоде — 1 из 1 931) |
| Средняя глубина инфо-визита | 1,11 просмотра |

Причина оказалась не в поведении, а в разметке: на старых страницах, которые и держат весь трафик (`/glossary/roi/`, `/blog/incrementality/`, `/glossary/cdp/`), контекстных ссылок на коммерческие страниц **не было вообще** — только пункт шапки. Перелинковка велась между инфо-страницами, а не в коммерцию, поэтому доля коммерческих входов и не сдвинулась.

**Как должно выглядеть** (из `/glossary/unit-ekonomika/` — там ссылка живёт в предложении и объясняет, зачем переходить):

> …а на [аудите CRM-маркетинга](https://crmgroup.ru/crm-marketing/) первым делом смотрим на частоту повторных заказов: обычно это самый дешёвый способ починить сходимость юнитов.

Критерий: ссылка стоит внутри мысли и отвечает на вопрос «что мне это даст», а не «вот наша услуга». Если такого места в статье нет — это сигнал, что статья не приземляется, и нужен абзац-мостик, а не ссылка.

**FAIL**, если в теле нет ни одной контекстной коммерческой ссылки. Указать конкретное место вставки и анкор.

### Канон по количеству

Канон: **2–4 внутренние ссылки, из них максимум 1 коммерческая**. Ссылки — только на каноничные опубликованные страницы: не линковать на черновики; если по теме есть дубли-каннибалы — линковать только на каноничную версию.

Если существует `<project>/data/internal-linking-rules.md` — **прочитать и следовать ему** (там правила и реестр каноничных целей). Для Фактора: `factor/data/internal-linking-rules.md`.

Опорная карта при отсутствии rules-файла (`factor/data/company-context.md` раздел 9):
- Платный аудит → `/services/platniy-audit/`
- Построение ОП → `/services/postroenie-otdela-prodazh/`
- Кейсы → `/case/`
- Блог (смежные статьи) → из `company-context.md`

Если ссылок меньше 2 — предложи конкретные места вставки с анкором. Если больше 4 — предложи, какие убрать.

## Gotchas

**🛡️ WAF / fail2ban (общая механика площадок).** Сервер банит IP за серию ошибочных или слишком частых запросов:
- после **401/403 НЕ ретраить** — это не транзиент: проверить креды (не ушёл ли плейсхолдер вместо пароля из secrets);
- между REST-запросами держать паузу 1–2 с (конвейер делает 10–20 запросов подряд);
- если в ответ пришла HTML-страница вместо JSON — это бан-страница WAF: остановиться и подождать, не долбить.


- **Считать символы явно** — «~50 символов» не годится. Считать точно.
- **H1 ≠ SEO Title** — разные тексты. H1 на странице, SEO Title в браузерной вкладке и сниппете.
- **FAQ из реального поиска, не придуманные** — использовать WebSearch для проверки реальных вопросов.
- **cover_tag — ЗАГЛАВНЫМИ** — это технические требования темы WP.
- **Не переписывать тело статьи** — только метаданные и SEO-оболочка.
