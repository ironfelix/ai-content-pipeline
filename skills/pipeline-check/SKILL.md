# Pipeline Check — контролёр конвейера статьи

Родился 27.08.2026 из разбора статьи «Удержание клиентов»: pipeline.md показывал ✅ по всем шагам,
а реально /editor шёл без фан-аута, /seo-optimizer не запускался вообще, /quality-gate не перепрогонялся
после поздних правок. владелец дважды ловил ИИ-паттерны в «прошедшем редактуру» тексте.

Четыре механизма развала, против которых построен этот скилл:
1. **Фолбэк становится дефолтом** — сбой оправдал ручной режим один раз, дальше ручной режим едет по инерции.
2. **Перебивки + возобновление «по памяти»** — после переключения приоритетов работа продолжается с того, что помнится, а не с первой незакрытой строки pipeline.
3. **Надувание статусов** — ✅ ставится за «похожее на шаг»; гейт паблишера читает эти же галочки, защита самоотключается.
4. **Соло-правка слепа к своим тикам** — убрал тире → построил всё на двоеточиях. Новый тик виден только счётчиком.

Поэтому принципы: **артефакт вместо галочки · исход вместо отчёта · pipeline.md — драйвер, не дневник.**

## Шаг 1 — Проверка по артефактам (галочкам не верить)

Для каждого этапа проверяется его **артефакт**, не строка в таблице:

| Этап | Артефакт | Проверка |
|---|---|---|
| /researcher | `{project}/research/{slug}-research.md` | файл есть; в нём разделы «H2 Plan» и «Уникальный угол»; в pipeline есть `## H2 Plan` и непустой `intent_cluster:` |
| /writer | `articles/{slug}/draft.md` | файл есть; H1 совпадает по смыслу с pipeline; H2 из текста ⊇ H2 Plan (сверить заголовки) |
| /methodology-gate | строка в pipeline | только для factor; для остальных проектов авто-N/A с причиной «нет файла методологии» |
| /editor | находки фан-аута | в pipeline есть запись о ревьюерах с ЧИСЛОМ находок; НО решает Шаг 3 (охотник): если охотник даёт FAIL — редактура не считается, что бы ни было записано |
| /fact-checker | секция `## Fact-check` в pipeline | есть реальные записи (не шаблонные комментарии) или счётчики T1/T2/FAIL |
| /quality-gate | штамп в `{project}/RULES_CHECKLIST.md` | грепом: слаг + дата + числа; штамп датой ПОЗЖЕ последней правки draft.md (mtime), иначе — просрочен |
| /seo-optimizer | секция `## SEO pack` в pipeline | h1/seo_title/seo_desc/cover_* заполнены; посчитать символы: Title ≤60, Description 120–155. Числа в скобках не принимать на веру — пересчитать |
| /publisher sync | `wp_post_id`, `google_doc_id` в pipeline | REST GET черновика: status=draft, тип верный |
| /designer | строка 8b + контент WP | в WP raw число `blog-gallery` = заявленному числу схем; меток `[ВИЗУАЛ` в WP не осталось; «0 схем: причина» — тоже PASS |

Результат шага — таблица «этап → PASS / WARN / FAIL / N/A → почему».

## Шаг 5 — Вердикт, честные статусы, решение

1. **Вывести сводную таблицу** всех проверок.
2. **Переписать pipeline.md по правде**: липовые ✅ понизить до ⚠️ с причиной («без фан-аута», «вручную, скилл не запускался», «штамп старше правок»). Фолбэк — это ⚠️-долг, не завершение.
3. **Составить план дочинки** по карте зависимостей — что тянет что:

```
draft.md изменился после этапа X        → X просрочен
editor FAIL                             → фан-аут ревьюеров → quality-gate → пересборка WP+Doc
quality-gate просрочен/нет штампа       → /quality-gate (скиллом, со штампом)
seo-optimizer нет артефакта             → /seo-optimizer (скиллом)
sync FAIL при валидном draft            → только пересборка (WP и/или Doc)
designer: метки в WP / число схем ≠     → /designer
вёрстка: маркеры/якоря разошлись        → пересборка конвертером по эталону
```

4. **mode=report** → показать план и остановиться. **Дефолт** → выполнить план: недостающие шаги
   перезапускаются **скиллами** (не «по мотивам»), пересборки — проверенным конвертером проекта
   со счётом слов до/после.
5. 🔒 **Публикацию этот скилл не выполняет никогда** — финальный статус всегда «ждёт „публикуем“».

## Gotchas

- **Галочка без артефакта = не сделано.** Это главный закон скилла, исключений нет.
- **Числам в скобках не верить** («50 симв.») — пересчитывать len().
- **WP читать только `context=edit` → `content.raw`** — rendered ломает блоки и раскрывает шорткоды.
- **Даты**: штамп quality-gate сверять с mtime draft.md — правка текста обнуляет гейты после себя.
- **Свои инлайн-правки не считаются скиллом**: если в истории pipeline есть «правил вручную» — соответствующий этап автоматически ⚠️.
- **Охотник главнее отчёта редактора**: красивая запись о ревью при FAIL охотника = редактура не зачтена.
- **Не плодить полотно**: чекер не редактирует текст сам — он только диагностирует и вызывает нужные скиллы.
- WAF: между REST-запросами пауза 1–2 с; после 401/403 не ретраить, проверить креды.
