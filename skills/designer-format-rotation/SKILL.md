# Designer format rotation

Использовать, когда визуалы в статьях начинают выглядеть одинаково или дизайнер снова уходит в карточки со списками.

## Принцип

Визуал не украшает статью. Он объясняет отношение, которое текстом читается хуже:

- путь клиента;
- смену ролей;
- развилку решения;
- сравнение вариантов;
- зрелость системы;
- поток данных;
- разбор экрана, письма или диалога;
- антипример;
- вклад факторов в результат.

## Роли

| Кто | Что решает |
|---|---|
| Редактор | Где нужна схема и что она должна вынести |
| Дизайнер | Какой формой показать смысл |
| Publisher | Не публикует, пока visual step не закрыт |

Редакторская метка:

```markdown
[ВИЗУАЛ: заголовок=… | данные=… | смысл=…]
```

Живой пример:

```markdown
[ВИЗУАЛ: тип=live-example | источник=CRM | смысл=показать где теряется лид | данные=статусы, ответственный, дата, следующий шаг]
```

`источник=` называет предмет рынка, не шаблон: `сайт`, `интерфейс`, `письмо`, `бот`, `CRM`, `дашборд`, `воронка`, `конкурент`, `до-после`.

## Каталог форм

Базовые:

- flow steps;
- timeline;
- checklist;
- before/after;
- decision tree;
- system map;
- error cards;
- comparison columns;
- 2×2 matrix;
- concept cards;
- funnel;
- stats block;
- relation map.

Второе поколение:

- journey map;
- service blueprint;
- role lanes;
- branching flow;
- maturity ladder;
- scorecard;
- decision matrix;
- quadrant plot;
- radar;
- heatmap;
- feedback loop;
- data-flow map;
- object anatomy;
- annotated screen;
- teardown;
- anti-pattern map;
- benchmark bars;
- share grid;
- waterfall.

Живые примеры:

- annotated website;
- CRM screen;
- bot dialogue;
- email teardown;
- market example card;
- screen-by-screen journey;
- dashboard snapshot;
- before/after screen.

## Правила выбора

1. Сначала смысл раздела, потом форма.
2. Повтор формы допустим только если она сильнее альтернативы по содержанию.
3. Разнообразие, которое врёт о смысле, хуже повтора.
4. Если данных для формы нет, не придумывать. Выбрать другую форму или вернуть 0 схем.
5. Карточки со списком — одна форма из многих, не дефолт.

## Чужие скриншоты

Чужой скриншот не брать. Если нужен пример с рынка, рисовать синтетический мокап и подписывать: «синтетический пример по рыночному паттерну». Указать `refs`, на какие открытые источники/паттерны смотрели.

Свой кадр допускается только с `origin: "own"` и пояснением `origin_note`.

## Что писать в result

В конце дизайнерского шага зафиксировать:

```json
{
  "status": "ok",
  "formats": ["journey-map", "email-teardown", "heatmap"],
  "notes": "почему выбраны эти формы и где сознательно не ставили схему"
}
```

Если схем нет:

```json
{
  "status": "ok",
  "formats": [],
  "notes": "0 схем: тема короткая, визуал был бы декором"
}
```
