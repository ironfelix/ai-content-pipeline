# Link Check — чекер битых ссылок

Машинка: `link_checker.py` (в папке скилла). По sitemap берёт все страницы, на каждой собирает `href`, проверяет статусы. Фильтрует WP-системный шум (xmlrpc, feed, RSD, wp-login).

## Запуск
```bash
python3 ~/.claude/skills/link-check/link_checker.py <домен> [max_pages] [--external] [--workers N]
```
- `<домен>` — с протоколом: `https://crmgroup.ru`
- `max_pages` — сколько страниц (0/пусто = все из sitemap)
- `--external` — проверять и внешние ссылки (по умолчанию только внутренние)
- `--workers N` — параллелизм (дефолт 8; для слабых/нестабильных серверов ставь 4)

## Как действовать
1. Уточнить домен(ы). Дефолт-список клиента: `https://crmgroup.ru`, `https://emailsoldiers.ru` (+ при необходимости yoursite.ru, agentiq.ru).
2. Прогнать сначала внутренние ссылки (быстро, главное по SEO/UX). Потом по желанию `--external`.
3. ⚠️ **Хрупкие серверы беречь:** emailsoldiers (был disk-инцидент) — `--workers 4`, кап 200-300 страниц, не гнать весь сайт залпом.
4. Большой прогон — пускать в фоне (`run_in_background`), это нормально.
5. Отчёт: сгруппировать битые по типу (404 внутренние = чинить; битые картинки = перезалить/убрать; мёртвые внешние = заменить/убрать). Для каждой битой показывать страницу-источник (`←`).

## Починка найденного
- **Битая внутренняя ссылка / картинка в статье блога** — правится через WP REST (контент редактируется): найти правильный URL и заменить, либо убрать ссылку. crmgroup: `wp/v2/blog`, ES: `wp/v2/posts`. H1/Title лендингов НЕ через REST (правятся через FTP/functions.php — доступы клиентов в памяти проекта).
- Доступы WP REST (логин + пароль): брать из `<project>/project.md` или памяти проекта, не хранить в тексте скилла.

## Что считается шумом (не битое)
xmlrpc.php, `/feed`, `?replytocom`, `?rsd`, `?pingback`, `/comment-page`, `/trackback`, wp-login/wp-admin — авто-ссылки WordPress, игнорируются фильтром.

## Известные нюансы
- С 18.11.2026 ссылки проверяются ровно как написаны в HTML, слэш на конце больше не срезается. Раньше `rstrip('/')` давал ложные 404 и 301. Если в старых отчётах видишь массовые «404» на адресах без слэша, это был тот артефакт.
- Ссылки разбираются HTML-парсером, а не регуляркой: понимает минифицированный HTML без кавычек (`href=/uslugi/`) и `&amp;`. Плюс проверяются `img src` и `srcset`.
- Если со страниц не извлечено ни одной ссылки, скрипт выходит с кодом 2 и пишет «Результат НЕДЕЙСТВИТЕЛЕН». Это не «всё чисто»: сайт рендерится скриптом или режет ботов, проверять вручную.
- Кириллические URL кодируются автоматически (`urllib.parse.quote`).
- HEAD-запрос; если сервер не поддерживает (403/405/501) → повтор GET.
- Скрипт без внешних зависимостей (stdlib), запуск любым python3.
