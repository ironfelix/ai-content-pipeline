# Entity-граф: подключаться к Yoast, а не строить второй (бэклог #10)

> Применимо ТОЛЬКО к crmgroup.ru / emailsoldiers.ru (там SEO-схему отдаёт Yoast).
> На Факторе Yoast НЕТ — SEO-мета через ACF, этот раздел неприменим.
> Вынесено из publisher/SKILL.md (бывший раздел I-3 Шага 3).

Это **не** про буст в AI-ответах — там generic schema даёт минус. Смысл другой: связать страницы в один граф, чтобы поисковик видел за ними одну организацию, а не набор разрозненных документов.

🔴 **Сначала посмотреть, что уже отдаётся.** Проверка `/glossary/kpi/` 27.08 показала, что Yoast уже держит свой граф, а наш ручной блок его дублирует:

| Кто отдаёт | Узлы |
|---|---|
| Yoast | `WebSite @id=https://crmgroup.ru/#website`, `WebPage @id=<url>` (`isPartOf` → `#website`), `BreadcrumbList @id=<url>#breadcrumb`, `ImageObject` |
| Наш ручной блок | `DefinedTerm`, **второй `BreadcrumbList`**, `FAQPage` — и ни у одного нет `@id` |

Замер 27.08 по четырём страницам: дубль `BreadcrumbList` только на `/glossary/kpi/`, у `/blog/incrementality/` по одному узлу каждого типа. На EMS (`/blog/all-about-lead-generation`, `/glossary/cdp`) схема и FAQ-аккордеоны на месте — работа 17–19.08 живая. То есть дубль узкий, не системный: чинить при дожиме конкретной страницы, а не проходом по сайту.

Отсюда три вывода, и они важнее любого нового узла:

1. **Не создавать вторую сущность.** Yoast уже держит `#website`. Наш блок должен **подключаться** к нему через `@id`, а не заводить параллельный граф. Узел без `@id` в графе не участвует — он просто висит.
2. **Убрать дубль хлебных крошек.** Второй `BreadcrumbList` конкурирует с тем, что уже отдаёт Yoast. Чинить при первом же дожиме страницы, отдельным проходом по сайту не ходить.
3. **Organization отсутствует.** Yoast отдаёт только `WebSite`. Пока Organization не заведён в настройках Yoast, ссылаться `publisher: {"@id": …#organization"}` не на что — сначала завести там, потом ссылаться.

Как выглядит правильное подключение (наш блок ссылается на чужой `@id`, ничего не дублируя):

```json
{"@context":"https://schema.org","@graph":[
  {"@type":"FAQPage","@id":"https://crmgroup.ru/glossary/kpi/#faq",
   "isPartOf":{"@id":"https://crmgroup.ru/glossary/kpi/"},
   "mainEntity":[ ... ]}
]}
```

⚠️ **Проверять схему только с редиректами и браузерным User-Agent.** EMS отвечает `301` на URL со слэшем, а без `-L` curl отдаёт ноль байт — и проверка показывает «схемы нет» там, где она есть. На этом я 27.08 чуть не записал в баги живую работу. Команда:
```bash
curl -sL -A "Mozilla/5.0" "<url>" | grep -oE '"@type": *"[A-Za-z]+"' | sort | uniq -c
```

**Что проверить перед добавлением:**
- `@id` буквально совпадает с тем, что отдаёт Yoast — расхождение в слэше или протоколе рвёт связь;
- ни один тип не появляется на странице дважды (проверить `grep -o '"@type":"[A-Za-z]*"' | sort | uniq -c`);
- в `sameAs` только живые профили: мёртвая ссылка хуже отсутствия, она заявляет тождество с тем, чего нет;
- ⛔ Instagram и Facebook в `sameAs` не ставить — Meta запрещена в РФ;
- у EMS свой домен и свой `#website` — сайты разные, склеивать в одну сущность нельзя.

**Порядок внедрения:** только на новых и дожимаемых страницах. Задним числом по всему сайту не проходить — массовое добавление JSON-LD на существующие страницы это ровно тот случай, где Ahrefs намерил −4,6%.

🔴 **Про HowTo отдельно — не предлагать его снова.** Google убрал HowTo из расширенных сниппетов в августе 2023, Яндекс их никогда не поддерживал. Визуального выигрыша в выдаче нет ни в одном из наших поисковиков, а в замере Ahrefs такая разметка попадает в ту самую generic-группу с −4,6%. Проверено 26.08.2026 при разборе smyslokod.ru (у них стоит Article + HowTo + Person + Organization + Breadcrumb на каждой статье) — копировать этот стек не надо.
