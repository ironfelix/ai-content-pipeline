# AI Content Pipeline — скиллы для Claude Code

AI Content Pipeline — это набор скиллов для [Claude Code](https://claude.ai/code), который собирает SEO-статью как производственный конвейер: исследование → черновик → методологическая проверка → редактура → фактчек → SEO-упаковка → визуалы → публикация → замер результата.

Идея простая: один агент не должен «и придумать, и написать, и проверить, и сверстать». Каждый скилл отвечает за свой участок работы и оставляет артефакт в `pipeline.md`, чтобы следующий шаг понимал, что уже сделано и где статья заблокирована.

**Методология и живая демонстрация:** [ironfelix.github.io/ai-seo-pipeline](https://ironfelix.github.io/ai-seo-pipeline/)
**Скиллы на GitHub:** [github.com/ironfelix/ai-content-pipeline](https://github.com/ironfelix/ai-content-pipeline)

## Автономный слой (август 2026)

Скиллы выросли в **агентство на сервере**: оркестратор гоняет их без человека в цикле.

- **Планировщик-портфель** каждую среду собирает неделю работ из сигналов (позиции, заявки по страницам, очередь углубления, дыры конкурентов) и раскладывает бюджет по корзинам: верное / ставки роста / инфраструктура / разведка. Пустых недель не бывает.
- **Механические стражи до модели и после**: стиль как код (тире, обороты, чужая вёрстка), самопроверка собранной страницы (словарь классов выводится из живых страниц сайта), для точечных правок — baseline-режим: валит только то, что появилось.
- **Путь в лид как обязательство**: страница не выходит без контекстной ссылки на релевантную услугу. Новый лёгкий скилл `/linker` ставит такие ссылки на существующие страницы — одна фраза, одна ссылка, очередь ранжирована спросом.
- **Ярусы согласования**: мелкая обратимая правка публикуется сама (механический страж размера и чистоты), средняя — через окно вето 20 ч (молчание = «да»), новые статьи — только словом владельца. Любая правка отменяется фразой «откати <имя>» — прежний текст хранится.
- **Ревизор и сторож**: шаг без артефакта — не сделанный шаг; зависания, устаревший код в памяти процесса и «остановленные» прогоны с уже доехавшей работой ловятся автоматически.

Подробно — в разделе «Автономность» на [странице методологии](https://ironfelix.github.io/ai-seo-pipeline/#agency).

## Как это работает

### Обновление 11.09.2026 — визуалы и живые примеры

Рабочий пайплайн ушёл дальше августовской версии: теперь статья не просто проходит текстовые гейты, а получает осмысленные визуальные блоки.

Главные изменения:

- `/editor` размечает места под визуалы как слоты: `[ВИЗУАЛ: заголовок=… | данные=… | смысл=…]`.
- `/designer` не выбирает шаблон по привычке. Он сначала смотрит смысл раздела, историю форматов сайта и только потом выбирает форму.
- Каталог расширен до 40 форм: journey map, service blueprint, maturity ladder, heatmap, teardown, annotated screen, CRM screen, bot dialogue, email teardown и др.
- Карточки со списками больше не дефолт. Единица схемы — отношение, процесс, экран, письмо или рыночный пример.
- Чужие скриншоты не копируются. Живые примеры рисуются как синтетические мокапы по рыночному паттерну с указанием refs; свои скриншоты можно ставить только с пометкой `origin: "own"`.
- `/publisher` должен видеть закрытый `/designer`: либо вставлены схемы, либо явно зафиксировано «0 схем» с причиной.

Связанный support-skill: `skills/designer-format-rotation/SKILL.md`.


Один запрос типа «напиши статью про управление отделом продаж» проходит через цепочку специализированных агентов:

```
/researcher → /writer → /methodology-gate → /editor → /fact-checker → /quality-gate
     → /seo-optimizer → /publisher sync → /designer → /publisher → /tracker → /page-optimizer
```

Что происходит по смыслу:

1. `/researcher` собирает фактуру и угол статьи, чтобы текст не был пересказом топ-10.
2. `/writer` пишет первый черновик по исследованию.
3. `/methodology-gate` проверяет, что статья не врёт про продукт, этапы, роли и метрики.
4. `/editor` делает текст человеческим и размечает места, где нужны визуалы.
5. `/fact-checker` проверяет цифры, источники и спорные утверждения.
6. `/quality-gate` блокирует публикацию, если текст деревянный, сырой или не ведёт в лид.
7. `/seo-optimizer` собирает H1, title, description, FAQ и внутренние ссылки.
8. `/publisher sync` создаёт черновик в WordPress и Google Doc для ревью.
9. `/designer` добавляет схемы, разборы экранов, письма, CRM-мокапы и другие визуалы по смыслу разделов.
10. `/publisher` после подтверждения владельца публикует статью.
11. `/tracker` и `/page-optimizer` смотрят результат и улучшают уже опубликованную страницу.

`pipeline.md` — журнал и state machine статьи. Если шаг не оставил артефакт, он не считается сделанным. Если гейт не пройден, следующий агент не должен «надеяться», что всё нормально.

## Агенты

### 1. `/researcher` — понять тему до текста
Собирает конкурентов, поисковый интент, смежные вопросы и факты, которых нет в обычной AI-статье. Его задача — дать автору материал и угол, а не просто список ключей.

**Вход:** тема / ключевой запрос
**Выход:** `research/slug-research.md` + стартовый `articles/slug/pipeline.md`

### 2. `/writer` — собрать первый черновик
Пишет статью по research report. Не занимается SEO-метаданными, публикацией и дизайном. Фокус — логика, структура H2, прямой ответ в начале и раскрытие query fan-out.

**Вход:** `research=путь/к/research.md`
**Выход:** черновик статьи

### 3. `/methodology-gate` — не дать статье соврать
Проверяет черновик против реальной методологии и продукта клиента: этапы, роли, метрики, границы услуги, обещания. Это замена экспертного «стоп, мы так не делаем».

**Вход:** черновик + контекст компании
**Выход:** `PASS` или список блокирующих искажений в `pipeline.md`

### 4. `/editor` — сделать текст живым и понятным
Убирает AI-паттерны, деревянные обороты, пустые H2 и обобщения. Добавляет голос бренда и конкретику. Теперь ещё размечает визуальные слоты для дизайнера: где нужен экран, схема, разбор письма, путь клиента или сравнение.

**Вход:** черновик / Google Doc / slug
**Выход:** отредактированный текст + метки `[ВИЗУАЛ: …]`

### 5. `/fact-checker` — проверить факты
Проверяет цифры, источники, имена, даты и сильные утверждения. Делит источники по надёжности: первоисточник, крупное медиа, неподтверждённое. Сомнительное либо правит, либо помечает.

**Вход:** отредактированный текст
**Выход:** исправленный текст + обновлённая база фактов

### 6. `/quality-gate` — остановить плохую публикацию
Автоматический редакционный гейт. Проверяет не только формальные вещи вроде длины, FAQ и H1, но и смысл: есть ли путь в услугу, не звучит ли текст как переводной SaaS-шаблон, не остались ли запрещённые обороты и пустые обещания.

**Вход:** статья после редактора и фактчека
**Выход:** `PASS` или конкретный список правок для возврата в `/editor`

### 7. `/seo-optimizer` — упаковать под поиск
Собирает H1, SEO title, description, FAQ, внутренние ссылки и проверяет H2 как поисковые запросы. Не переписывает всю статью, а доводит SEO-оболочку и маршрут пользователя.

**Вход:** slug статьи
**Выход:** SEO-пакет в `pipeline.md`

### 8. `/publisher sync` — создать черновики для ревью
Синхронизирует статью в WordPress draft и Google Doc. На этом шаге статья ещё не публикуется: владелец может посмотреть текст, внести правки и вернуть его в конвейер.

**Вход:** статья + SEO-пакет
**Выход:** WordPress draft + Google Doc + ID в `pipeline.md`

### 9. `/designer` — добавить визуальный слой
Берёт метки редактора и выбирает форму по смыслу: journey map, service blueprint, heatmap, teardown, CRM screen, bot dialogue, email teardown, dashboard snapshot и т.д. Карточки со списками больше не дефолт. Если визуал будет декором — честно фиксирует `0 схем` с причиной.

**Вход:** статья / WP draft / визуальные метки
**Выход:** PNG/SVG/HTML-визуалы, вставленные в черновик, или осознанный отказ от визуалов

### 10. `/publisher` — опубликовать после подтверждения
Финальный публикатор. Проверяет закрытые гейты, форматирует HTML, TOC, TL;DR, FAQ, Schema.org, ACF-поля, обложку и публикует только после явного подтверждения владельца.

**Hard gates:** `pipeline.md` PASS по обязательным этапам + закрытый `/designer` + явная команда «публикуем»
**Выход:** опубликованная статья на сайте

### 11. `/tracker` — измерить результат
После публикации смотрит позиции, видимость, AI-ответы, клики и страницы, которые можно усилить. Его задача — превратить публикацию в цикл улучшения, а не в «выложили и забыли».

**Вход:** slug или post_id
**Выход:** отчёт по позициям + action items в `pipeline.md`

### 12. `/page-optimizer` — улучшить живую страницу
Работает с уже опубликованной страницей: добавляет новые H2, FAQ, внутренние ссылки, уточняет блоки под запросы, где страница почти добралась до топа.

**Вход:** `post_id=123` или slug
**Выход:** обновлённая опубликованная статья + отметка в `pipeline.md`

## Дополнительные скиллы (аудит и онбординг)

Нужны не для каждой статьи, а на старте проекта или для аудитов.

- **`/marketing-audit`** — оркестратор аудита сайта: тех-SEO → контент/семантика → конкуренты и gap, по порядку.
- **`/knowledge-session`** — структурированное интервью с клиентом (~60 мин). Выдаёт `data/company-context.md` и `data/voice.md`, на которых работают writer/editor.
- **`/seo-tech-audit`** — технический аудит: robots, sitemap, индексация, мета, canonical, Core Web Vitals, структура URL.
- **`/seo-content-audit`** — семантическое ядро, кластеризация по интентам, покрытие страницами, дыры в контент-плане.
- **`/seo-competitors-gap`** — органические конкуренты через keys.so + gap-анализ (какие ключи есть у них и нет у нас).
- **`/audit-report-builder`** — собирает из research-файлов единый HTML-отчёт для клиента.

## Установка

### 1. Скопировать скиллы

```bash
mkdir -p ~/.claude/skills
cp -r skills/* ~/.claude/skills/
```

### 2. Создать project.md для своего проекта

```bash
cp project-template/project.md myproject/project.md
# Заполнить: WP_URL, WP_USER, WP_PASSWORD, SSH_HOST, бренд-голос, правила
```

### 3. Настроить .env

```bash
cp .env.example .env
# Добавить: KEYSO_API_TOKEN, YANDEX_WEBMASTER_TOKEN, GOOGLE_PSI_API_KEY
```

### 4. Первая статья

```bash
# В Claude Code:
/researcher тема="управление командой продаж" project=myproject
/writer research=myproject/research/upravlenie-komandoy-research.md project=myproject
/methodology-gate slug=upravlenie-komandoy project=myproject
/editor slug=upravlenie-komandoy project=myproject
/fact-checker slug=upravlenie-komandoy project=myproject
/quality-gate slug=upravlenie-komandoy project=myproject
/seo-optimizer slug=upravlenie-komandoy project=myproject
/publisher slug=upravlenie-komandoy project=myproject mode=sync
/designer slug=upravlenie-komandoy project=myproject
/publisher slug=upravlenie-komandoy project=myproject
```

## Ключевые принципы системы

**TL;DR-первый абзац.** По данным исследования 36 млн AI Overviews: 55% цитат берётся из первых 30% текста. Первый абзац должен давать полный ответ без опоры на остальную статью. Формула: `[ключ + прямой ответ] → [цифра из опыта] → [контр-интуитивная позиция]`

**Query fan-out.** Google AI генерирует 5–8 смежных запросов вокруг одного запроса. /researcher строит кластер этих вопросов, /writer закрывает каждый вопрос отдельным H2.

**Non-commodity check.** Контент который можно заменить промптом «напиши статью про X» — AI не цитирует. Нужен хотя бы один элемент: кейс с числами, позиция с которой часть читателей не согласится, или факт которого нет у конкурентов.

**pipeline.md как state machine.** /publisher не публикует без PASS по всем этапам. Каждый скилл записывает свой результат. История каждой статьи сохраняется.
